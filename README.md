# QA Inspector v0.8

Нейтральне локальне Chrome Extension Manifest V3 для перегляду CSS, збирання даних сторінки/сайту та порівняння з JSON дизайн-системи або вибраним шаром Figma. Жоден проєкт не обраний за замовчуванням. Для перегляду CSS файл не потрібний.

## Встановлення

1. Google Chrome 116+: відкрийте `chrome://extensions`, увімкніть Developer mode.
2. Load unpacked → виберіть **extension/**. Немає збірки, npm install чи бекенда.
3. Якщо розширення вже встановлено, натисніть ↻ на його картці, закрийте й відкрийте панель.
4. Відкрийте потрібну звичайну вебсторінку та натисніть іконку QA Inspector. Панель залишається відкритою праворуч/ліворуч відповідно до налаштувань Chrome.

Для першого запуску на сайті може знадобитися дозвіл Chrome. У допомозі є **Надати доступ до цього сайту**. Доступ запитується до поточного хоста, без постійного дозволу на всі сайти. Для localhost порт не обмежується host permission Chrome. Для file:// вручну ввімкніть «Дозволити доступ до URL файлів». chrome://, Web Store та інші захищені сторінки Chrome недоступні. Вбудований браузер Codex не підтримує side panel — використовуйте звичайний Chrome.

## Три вкладки

**Компонент.** Увімкніть пікер і наведіть мишку. На сторінці видно розміри/padding/gap, у панелі — структуровані групи «Текст», «Відступи та проміжки», «Розміри», «Кольори», «Кути та вигляд». Клік фіксує, ↑/↓ змінюють рівень у DOM, Alt вибирає батьківський блок, Esc завершує. Для тексту/іконки всередині кнопки за замовчуванням вибирається кнопка.

**Сторінка.** Скан поточної сторінки: список елементів, знайдені шрифти/кольори/відступи, пошук за назвою/текстом. Спочатку показуються до 60 карток, решта — кнопкою «Показати ще»; експорт містить весь знімок до ліміту сканера.

**Сайт.** Автоматичний обхід внутрішніх посилань, прогрес, зупинка, результати за адресами та деталізація окремої сторінки. Без JSON використовуються поточний хост і ліміт 20 адрес. За ввімкненого еталона — його scope/crawl. Для нових фонових вкладок потрібен host access, одного activeTab недостатньо.

Кожна вкладка має власні дані, фільтр і експорт **JSON / Markdown / копіювання**. Перехід між вкладками не замінює інші результати. Перехід із компонента завершує живий пікер, зберігаючи останні дані. Фоновий обхід продовжується, поки ви користуєтеся іншими вкладками.

## Без еталона

Пікер, сторінка та сайт працюють без завантаження файлів. Зчитуються фактичні computed CSS: typography, кольори, padding, margin, gap/rowGap/columnGap, border-box dimensions, radius, border, display/alignment, shadow/backgroundImage.

Це **витягування даних**, а не оцінка правильності дизайну. Немає Pass/Fail або зеленого «відповідає». У звіті явно вказано, що відповідність не оцінювалася. Розміри є фактичними rendered border-box; transformed елемент може мати візуальний розмір, відмінний від CSS width/height.

JSON експорт містить URL, час, елементи, DOM-селектори, текстові підписи та фактичні стилі. Це дані знімка, а не автоматичне відновлення авторської дизайн-системи чи вихідного CSS.

## Необов’язковий JSON

Завантажте JSON/ZIP дизайнера. За успішного імпорту **Порівнювати з цим JSON** вмикається; його можна вимкнути або прибрати файл повністю. Із вимкненим перемикачем можна досліджувати інший сайт, навіть якщо збережений JSON призначений для іншого домену.

Після завантаження нового еталона/зміни теми старі порівняльні результати очищаються; фактичні знімки без еталона залишаються. Кожен звіт підписаний: «CSS-дані без еталона» або «Порівняння з …». Збережені результати відновлюються після повторного відкриття, але не оновлюються автоматично.

Підтримуються:

- **QA-конфіг**: конкретний selector → компонент → властивості/токени/допуски. Перевіряє роль компонента за правилами дизайнера.
- **Сирі Tokens Studio/DTCG**: набори токенів, alias, теми. Перевіряє наявність значення серед дозволених токенів, **не правильність вибору токена для конкретного компонента**. Наприклад, 16px може бути допустимим spacing, але кнопка за правилами може вимагати 12px.

Мінімальний QA-конфіг:

```json
{
  "schemaVersion": 1,
  "name": "My Design System",
  "scope": { "origin": "https://example.com", "pathPrefix": "/" },
  "defaultBrand": "default",
  "defaultTheme": "light",
  "contexts": {
    "default/light": { "button.height": "40px" }
  },
  "rules": [{
    "selector": ".button-primary",
    "name": "Primary Button",
    "properties": {
      "height": { "token": "button.height", "tolerance": 0.5 }
    }
  }]
}
```

Бренд/тема автоматично читаються з data-brand/data-theme або defaultBrand/defaultTheme. Невідомий контекст зупиняє порівняння, а не вгадується. Для сирих токенів тему можна вибрати у панелі. Вибір теми змінює еталон, а не CSS сайту.

Порядок правил явний: пізніші правила замінюють очікування тієї самої властивості для елемента, що збігся. Це не автоматичний розрахунок CSS specificity. Для елемента без правила ручний пікер покаже фактичні значення як Not comparable, а не Fail. Автоматичний скан обліковує елементи без мапінгу окремо.

## Імпорт Tokens Studio та ZIP

Legacy value/type; базовий DTCG $value/$type, успадкований тип груп; alias {path.to.token}; typography composite; px/rem dimension; sRGB color; HSL lighten/darken та alpha для #RRGGBB. DTCG typography lineHeight-number є множником fontSize. Font family у режимі токенів перевіряється як задекларована назва у stack, не фактично відмальований гліф.

ZIP може містити один QA JSON, один bundle або token sets із $themes.json/$metadata.json. Один QA-конфіг має пріоритет над сирими наборами в архіві. Themes комбінуються за групами; tokenSetOrder визначає порядок; source вирішує посилання, але не потрапляє до каталогу дозволених значень; disabled виключається. Невалідний файл не замінює попередній еталон.

Ліміти: файл 8 МБ, розпаковані JSON сумарно 16 МБ, до 100 JSON-файлів, 20000 токенів на тему, 30 контекстів, 500 правил. ZIP розпаковується в пам’яті; код із нього не виконується. JSZip постачається локально з ліцензією у vendor/.

Графові токени, $root/JSON Pointer, довільні math expressions, повний набір колірних просторів і всіх трансформацій Tokens Studio не підтримуються. Непідтримувані типи пропускаються з повідомленням. Невідомий модифікатор зупиняє імпорт замість неправильного перетворення.

## Обхід сайту

Необов’язкові параметри QA JSON:

```json
"crawl": {
  "startUrls": ["/"],
  "includeLinkedPages": true,
  "maxPages": 20,
  "readySelector": "main",
  "settleMs": 600,
  "timeoutMs": 12000
}
```

За замовчуванням початок — активна сторінка, автоматичний пошук a[href], до 20 адрес; maxPages можна задати від 1 до 50. Зберігаються SPA hash-маршрути #/…; #section не створює дублікати. Відсікаються зовнішні посилання, файли для завантаження й типові logout/delete/remove адреси; tracking-параметри очищаються. До 3000 посилань на сторінку, до 2000 знайдених адрес у черзі.

Сторінки без a[href] додайте до startUrls. Сканер не натискає кнопки, не надсилає форми й не відкриває діалоги. Завершення обходу означає завершення знайдених/заданих адрес, а не гарантію виявлення кожного можливого стану вебзастосунку.

readySelector очікує наявність елемента, settleMs — час відмальовування. Сторінки у фонових вкладках використовують звичайну сесію Chrome, але sessionStorage/тема можуть відрізнятися від початкової вкладки. Автоматичний контекст знімається на кожній сторінці окремо.

Обхід іде у service worker; його вкладки автоматично закриваються. Зупинка зберігає частковий звіт. Закриття панелі не зупиняє роботу. Якщо Chrome перезапустить worker під час обходу, стан буде позначено перерваним. Після закриття Chrome робота не продовжується.

Детальні результати обходу мають бюджет близько 4.5 МБ за консервативною оцінкою; понад нього зберігається тільки підсумок, із явною позначкою. Помилка завантаження не вважається успіхом і не зупиняє наступні адреси. Counts на різних сторінках можуть включати ті самі повторювані компоненти.

## Межі та приватність

До 1500 видимих кандидатів на сторінку; досягнення ліміту позначається. Приховані/inert, iframe, Shadow DOM і псевдоелементи пропускаються; lazy-loaded елементи потребують відображення й повторного скану. Не перевіряються доступність, контрастність, реальні гліфи та поведінка компонентів. Тіні/зображення фону читаються у режимі даних, але не порівнюються engine якості.

Порівняння нормалізує px, fontWeight, family, HEX/RGB(A)/transparent; tracking normal = 0, em/rem розв’язуються від fontSize/root. Допуски задає JSON. Градієнт і transform/zoom можуть дати Not comparable. Прозорий RGBA не компонується з фоном предків.

Немає власного сервера, аналітики чи завантаження звітів у хмару. Figma підключається окремо за бажанням користувача: запити йдуть безпосередньо до api.figma.com. Еталон і вибрана вкладка — storage.local; останні знімки/обхід — storage.session. Дані містять URL, текст/aria-label елементів і CSS; вони можуть містити відомості зі сторінки. Розширення їх нікуди не надсилає. Обхід завантажує перевірювані сторінки звичайним браузером, із їхніми звичайними запитами.

Постійний host permission — лише file:///*. Для сайтів використовуються activeTab або необов’язковий дозвіл поточного хоста. Немає спеціального дозволу чи завантаження будь-якого конкретного проєкту.

## Приклади та перевірка

Додаткові приклади Atlas залишені лише у designer/ і fixtures/ для регресійних перевірок. У пакеті extension/ немає Atlas-системи або кнопки її завантаження. Документація формату для дизайнера — designer/README.md.

```sh
npm test
```

34 тести логіки, імпорту, нормалізації, crawl, відсутності хибного Pass без еталона, fingerprint і збереження часткового звіту.

Браузерні перевірки (Playwright + встановлений Chrome, шлях до виконуваного файла можна змінити):

```sh
QA_PLAYWRIGHT=/absolute/path/to/playwright node tests/browser-smoke.cjs
QA_PLAYWRIGHT=/absolute/path/to/playwright node tests/extension-smoke.cjs
```

Browser smoke перевіряє незалежні вкладки, збирання/експорт без JSON, порівняння/його вимкнення, імпорт ZIP, збереження й layout; транспорт Chrome API імітується. Extension smoke встановлює справжній MV3 у тимчасовий профіль та перевіряє пікер, сторінку, фоновий обхід трьох нейтральних тестових сторінок і порівняння, яке знаходить 44px замість 40px. Лише тестова копія manifest отримує host grant локального fixture; робочий manifest залишається без спеціальних хостів. Тимчасовий HTTP fixture існує лише під час тесту й не є залежністю розширення.

Додатковий regression sample `tests/atlas-live.cjs` використовує опублікований сайт та файл прикладу з designer/; він не потрібен для роботи інспектора. Приклади можна відтворити `npm run build:atlas`.

## Еталон із Figma · v0.8

1. Відкрийте потрібний сайт у Chrome, потім панель QA Inspector → **Посилання Figma**.
2. Розкрийте **Доступ до Figma**. У Figma створіть Personal access token із правом **file_content:read** і доступом до файлу. Вставте його в поле пароля та натисніть **Зберегти токен і продовжити**. Не передавайте токен у чаті чи репозиторії.
3. У Figma виберіть потрібний фрейм, брейкпоінт або компонент → **Copy link to selection**. Вставте посилання з node-id у розширення.
4. Натисніть **Завантажити з Figma**. Chrome попросить дозвіл до api.figma.com.
5. Оберіть потрібний фрейм або вкладений шар зі списку назв і розмірів. Для макета всієї сторінки можна ввімкнути **Перевіряти ширину браузера як брейкпоінт**. Для картки чи кнопки ця опція зазвичай не потрібна.
6. Натисніть **Використати вибраний шар** → **Обрати компонент** та клікніть відповідний блок на сайті. Якщо потрібен контейнер, використовуйте Alt або стрілку вгору під час вибору.
7. Перегляньте «Зараз на сайті / Має бути», підсвітку, скопіюйте код або звіт. Для тексту обирайте текстовий шар Figma та відповідний DOM-елемент із текстом. Дочірні шари перевіряйте окремими парами.

**Межі першої версії:** порівнюється одна явно вибрана пара «шар Figma ↔ DOM-елемент». Це не автоматичне зіставлення всіх дочірніх шарів макета. Автоматичний обхід сайту з еталоном Figma вимкнений; для нього залишаються правила JSON. У вкладці «Сторінка» дія з Figma також відкриває вибір відповідного лейаута. JSON / ZIP і перегляд без еталона працюють як раніше.

Перевіряються доступні розміри, суцільні кольори, кути, padding і gap Auto Layout, типографіка текстового шару та сумісна рамка. Повороти, змішана типографіка, градієнти/зображення, складні рамки й перенесення Auto Layout мають обмеження, перелічені біля еталона. Властивості, які не вдалося надійно прочитати, не вважаються Pass. Збіг перевірених значень не підтверджує повну відповідність усього макета.

Токен зберігається тільки в **chrome.storage.session**, не входить у local cache еталонів, не передається на прод і не експортується у звіт. «Відключити Figma» видаляє його. Після завершення сесії браузера токен потрібно ввести знову; збережений еталон можна порівнювати без повторного запиту, але для оновлення потрібен доступ. Усі API-запити — read-only, обмежені часом і розміром. Доступ і ліміти залежать від Figma та прав користувача.

Перевірки: `npm test`, `npm run test:figma`. Браузерний тест завантажує справжнє MV3 розширення та використовує контрольовану відповідь Figma API; доступ до приватних живих файлів ним не підтверджується.

Підключення Figma подано двома кроками: до збереження токена видимі інструкція й поле ключа; після — статус «Токен збережено» та поле посилання. Джерела — доступні з клавіатури таби Figma / JSON–ZIP. Статус збереження не означає перевірений доступ до файлу: його перевіряє запит завантаження.
