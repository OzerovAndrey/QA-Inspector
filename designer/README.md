# Що дизайнер передає тестувальнику

Рекомендований варіант — **один QA-конфіг JSON у ZIP**. Для Atlas готовий `atlas-qa.zip`: його можна відразу завантажити в QA Inspector.

1. Токени з Tokens Studio є джерелом еталонних значень.
2. Для точного контролю компонентів дизайнер разом із розробником один раз задає мапінг: CSS-селектор → компонент → очікувані властивості/токени/допуски. Відступ, колір та інше визначаються роллю компонента, а не вгадуються за його поточним виглядом.
3. До JSON входять `schemaVersion: 1`, `name`, `scope` (origin і pathPrefix тестового сайту), `contexts` (вирішені значення токенів), `rules` (селектори та властивості). Приклад — JSON усередині atlas-qa.zip або designer/atlas-qa.json.
4. Передайте цей JSON або архів. QA завантажує його у розширення, відкриває відповідний сайт, запускає сторінку/ручний елемент і копіює звіт.

Приклад правила:

```json
{
  "selector": ".button-primary",
  "name": "Primary Button",
  "properties": {
    "height": { "token": "button.primary.height", "tolerance": 0.5 },
    "paddingLeft": { "token": "button.primary.padding", "tolerance": 0.5 },
    "gap": { "token": "button.primary.gap", "tolerance": 0.5 }
  }
}
```

Токени з цих правил мають бути присутні у кожному contexts. Для Light/Dark додайте потрібні контексти. Базові правила ставте раніше, винятки/hover/disabled — після них. Значення `value` можна використовувати для фіксованої вимоги без токена. Для staging оновіть scope.origin/pathPrefix. Не встановлюйте компонентний scope на чужий сайт із іншою версткою.

Самі токени без мапінгу також можна передати JSON або ZIP. Приклад `atlas-tokens.zip` містить окремі набори й локально підготовлені $themes/$metadata. Інспектор перевірятиме наявність значень серед токенів, а не правильність вибору токена для конкретного компонента. Він прямо позначає цей режим.

Не потрібно завантажувати JSON на сервер або підключати Figma. Генерація точного QA-конфігу з довільного Tokens Studio експорту ще не автоматизована: роль компонента не можна достовірно визначити лише з палітри значень.

## Автоматична перевірка сайту

До конфігу можна додати crawl.startUrls (список URL), crawl.includeLinkedPages (чи шукати посилання), crawl.maxPages (1–50), crawl.readySelector, crawl.settleMs та crawl.timeoutMs. У готовому atlas-qa.zip уже є старт #/overview, автоматичний пошук посилань і ліміт 12 адрес.

Для повноти додайте сюди розділи, які недоступні через a[href]. Для staging змініть scope.origin/pathPrefix і, за потреби, стартові URL. Перевірка не натискає кнопки й не відкриває діалоги. Окремі стан/бренд/тему перевіряйте повторним запуском на відповідному стані сайту: вибір теми в інспекторі змінює еталон, а не тему сайту.

У v0.7 JSON необов’язковий: QA може спочатку зібрати CSS-дані будь-якого доступного сайту без еталона. Після завантаження вашого файлу ввімкнеться перемикач «Порівнювати з цим JSON»; його можна вимкнути, не видаляючи файл.
