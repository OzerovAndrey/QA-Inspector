# Контекст проєкту · v0.7

QA Inspector — локальний Chrome Extension Manifest V3 для інспекції CSS та перевірки відповідності дизайн-системі.

## Поточна поведінка

- Компонент: наведення показує computed CSS, клік фіксує результат; Esc завершує вибір, стрілки вгору/вниз переходять між батьком/нащадком.
- Сторінка: збір властивостей знайдених елементів.
- Сайт: обхід сторінок у межах дозволеного сайту з прогресом, скасуванням і частковим звітом.
- Без еталона доступне витягування даних. Імпорт JSON/ZIP вмикає необов'язкове порівняння.
- Кожна вкладка має власні результати та експорт JSON/Markdown.

## Де що лежить

extension/ — готове розширення, panel.* — інтерфейс, picker.js — вибір елементів, scanner.js — зчитування, scan-core.js — оцінювання, import-system.js — імпорт, site-runner.js — обхід.

demo/ — локальна демосторінка; designer/ — приклади; fixtures/atlas/ — тестові джерела з походженням у PROVENANCE.md. Atlas не є обов'язковим сайтом продукту.

## Перевірки

npm test — тести нормалізації, імпорту, порівняння та обходу.

npm run test:browser — інтерфейс і CSS у браузері з імітацією API Chrome.

npm run test:extension — реальне MV3 розширення на локальному тестовому сайті, тимчасовий профіль. Потрібен Chrome/Chromium з підтримкою Extensions.loadUnpacked через CDP.

Для браузерних тестів: npm ci, потім npx playwright install chromium. На macOS використовується встановлений Google Chrome; QA_CHROME_PATH задає інший виконуваний файл. QA_PLAYWRIGHT дозволяє вказати зовнішню інсталяцію Playwright.

## Подальша робота

Покращувати зрозумілість даних та еталонів, сумісність імпорту і точність зіставлення. Не видавати збіг зі словником токенів за підтвердження правильності конкретного компонента. Усі нові можливості перевіряти на нейтральних прикладах.

## Оновлення інтерфейсу · 26 жовтня 2026

Три візуальні області: темна шапка з логотипом, біла робоча картка й окрема картка результатів. Кнопки мають іконки відповідного режиму. Активний пікер має зелений стан кнопки й курсор-хрестик на сайті; завершення прибирає курсор. Іконки Chrome: extension/icons/ (16/32/48/128 PNG), джерело — logo.svg.

## Стан сторінки

Еталон і результати прив’язані до вкладки та URL. Перехід на іншу сторінку, перезавантаження або перемикання на іншу вебвкладку скидає попередню перевірку. «Скинути все» також зупиняє пікер/обхід і видаляє еталон та результати з локального сховища інспектора.

Еталони тепер зберігаються окремо за origin сайту (для file:// — за папкою). Перехід очищає лише результати поточної сторінки; повернення відновлює JSON, режим порівняння й тему. «Скинути все» видаляє всі збережені еталони. Дозвіл tabs використовується для визначення адреси активного сайту.

Інтерфейс — технічна панель із палітрою Focus: фіолетовий #5148E5, світлі фіолетові поверхні та зелені primary-кнопки в тон #168A73 (заливка #137F69 для читабельності білого тексту). brand-theme.css підключений після базового panel.css. Блоки й поля мають радіус 16px, кнопки та таби — pill. Secondary-кнопки світло-сірі з рамкою, текстові дії фіолетові. button-icons.js додає монохромні іконки до статичних і динамічних кнопок. Семантичний колір збережений для результатів перевірки.

## Figma · v0.8

Універсальний read-only імпорт за selection link. figma-reference.js: парсинг URL, прямий REST GET, вибір видимих шарів, перетворення підтримуваних властивостей, self-contained scanFigmaTarget. figma-ui.js: джерела JSON/Figma, token session connect/disconnect, frame picker. Компонент перевіряє одну явну пару; Сторінка зіставляє дочірні шари автоматично (деталі нижче). Для брейкпоінта є явна опція перевірки innerWidth. Сайт-обхід з таким еталоном заблоковано. PAT у довіреному storage.local та X-Figma-Token до api.figma.com, не в кеші еталонів/репортах. При відновленні еталона з local cache не потрібен PAT до наступного оновлення з Figma. Тест npm run test:figma використовує нейтральний fixture API, не доступ до приватного файлу.

Токен Figma тепер зберігається постійно в storage.local з accessLevel TRUSTED_CONTEXTS, окремо від siteReferences/звітів. figma-credentials.js мігрує живий session token, відновлює між сесіями, видаляє при Disconnect або 401. Скидання еталонів не відключає Figma. Дату завершення визначає API Figma, не вгадувати її з ключа.

Режим Сторінка з Figma запускає scanFigmaPage без пікера. Еталон містить компактний source.layers: властивості, текст, parentId та sizing skips. Автозіставлення за явним data-figma-node-id, унікальним текстом і спільним батьком щонайменше двох шарів; неоднозначні обгортки пропускаються. CSS-значення не впливають на вибір відповідностей. figmaPage зберігає matched/total/unmatched для UI та експорту. Компонент зберігає явне ручне зіставлення. Старі кеші без layers оновлюються автоматично перед Page scan через refreshFigmaSystem. Той самий source.url/nodeId, зі збереженням checkViewport і відомого Fill/Hug для кореня. Запис нового еталона тільки після успішного отримання й перевірки. У loaded-system показуємо статус готовності й кнопку оновлення/повтору. Помилки доступу ведуть до підключення; старий еталон лишається.

Кольори в панелі (властивості, порівняльні таблиці, палітра та підсвітка) показуються як HSL із alpha через display-values.js. Сирі дані, порівняння, допуски й експорт CSS лишаються у початкових значеннях.

Порівняння Figma пропускає повністю прозорий backgroundColor без backgroundImage, а також динамічні осі FILL/HUG/DYNAMIC. Для фреймів/обгорток DOM визначаємо width:auto у блочному потоці, width:100% або flex-grow у горизонтальному Flex. Піксельна ширина таких обгорток не порівнюється. Текстові шари й фіксовані розміри залишаються у перевірці. Пропуски записуються в skippedChecks та звіт; порожній набір перевірок — Not comparable, а не Pass. JSON не змінено.

Компактна панель: panel-shell.js — UI-адаптер поверх незмінних ID/обробників, panel-shell.css — фінальний шар стилів. Хедер зі статусом/меню, режими → CTA → результати → згорнуте порівняння; split-експорт приховано без даних. Фіолетовий primary, зелений лише статус. Paste/drop делегують чинним імпортерам, autoApply у figma-ui.js застосовує точний linked node через старий useSystem. Налаштування й ручний вибір шару доступні у додаткових секціях. Деталі та ручний чекліст: docs/UI_REDESIGN.md.

Секція «Порівняти з Figma» тепер є постійно відкритим section (без акордеона), з кольоровим логотипом Figma в заголовку. Додаткові налаштування й шари лишаються згортуваними.
